# Установка и обновление CS2 Updater

Пошаговая инструкция для администратора дедика. Ставится **на хост-машину** (там же,
где крутится Wings), не в контейнер.

Справочник по всем переменным, настройке mount и разбору проблем — в
[service/README.md](README.md). Здесь только процедуры: поставить и обновить.

---

## Что вы получите

Systemd-сервис, который раз в 5 минут спрашивает у Steam, не вышел ли патч CS2.
Когда патч выходит — оповещает игроков, гасит CS2-серверы на этой ноде, обновляет
**одну** копию файлов игры через SteamCMD и поднимает серверы обратно.

Все CS2-контейнеры монтируют эту копию в `/mnt` и не качают игру каждый себе.
Десять серверов занимают на диске столько же, сколько один.

---

## Требования

| | |
|---|---|
| ОС | Debian 11+ или Ubuntu 20.04+ (нужен `apt`, `systemd`) |
| Права | пользователь с `sudo` |
| Диск | **не меньше 50 ГБ свободно** под файлы игры |
| Панель | Pelican Panel + Wings, доступна с этой машины |
| Сеть | исходящий доступ к `steampowered.com`, `github.com`, `metamodsource.net` |

Заранее подготовьте (это спросит установщик):

1. **URL панели** — без `/` в конце, например `https://panel.example.com`
2. **Application API token** — панель → **Admin** → API Credentials → **Application API**
3. **Client API token** — панель → **Account** → API Credentials → **Client API**
   ⚠️ Это **два разных** ключа из разных разделов. Подставите application-ключ
   вместо клиентского — получите HTTP 403.
4. **Node ID** — номер ноды, на которой стоят ваши CS2-серверы
5. **Docker-образ** — тот же, что указан в egg (по умолчанию
   `docker.io/scrender/base-files-cs2:latest`)

Клиентский ключ должен принадлежать аккаунту с правами **control** и **console**
на управляемые серверы — иначе updater не сможет их гасить и поднимать.

## Установка

### Шаг 1. Поставить git

```bash
sudo apt-get update && sudo apt-get install -y git
```

### Шаг 2. Проверить место на диске

```bash
df -h /
```

Свободного должно быть **больше 50 ГБ**. Если корень маленький, а место есть на
другом разделе — на шаге 4 укажите `BASE_DIR` там (например `/mnt/data/cs2_base`).

### Шаг 3. Склонировать репозиторий

```bash
sudo git clone https://github.com/Armatura-Create/CS2-pelican.git /opt/cs2-updater
```

```bash
cd /opt/cs2-updater/service
```

> Можно клонировать и в домашний каталог — тогда `git pull` не потребует `sudo`.
> Путь запомнится в systemd-юните, менять его потом = переустанавливать сервис.

### Шаг 4. Запустить установщик

```bash
sudo ./install.sh
```

Он поставит зависимости (`curl`, `jq`, `unzip`, 32-битные библиотеки для SteamCMD),
задаст вопросы, создаст `.env` с правами `600` и systemd-юнит.

Что отвечать:

| Вопрос | Что вводить |
|---|---|
| Имя systemd-сервиса | `cs2-updater` (суффикс `.service` добавится сам) |
| `BASE_DIR` | Enter = `/home/cs2_base`. Сюда ляжет игра, нужны те самые 50 ГБ |
| `SRCDS_APPID` | Enter = `730` |
| `STEAM_USER` | Enter = `anonymous` — для CS2 этого достаточно |
| `STEAM_PASS` / `STEAM_AUTH` | Enter (пусто). Нужны только для не-анонимной установки |
| `EXTRA_FLAGS` | Enter (пусто). `validate` — если хотите сверку файлов при каждом обновлении, это медленно |
| `PELICAN_URL` | URL панели, без `/` в конце |
| `PELICAN_APP_TOKEN` | Application API ключ |
| `PELICAN_API_TOKEN` | Client API ключ |
| `PELICAN_IMAGE` | Enter, если образ в egg стандартный |
| `PELICAN_NODE_ID` | номер вашей ноды |
| Интервал проверки версии | Enter = `300` сек |
| Время отсчёта перед рестартом | Enter = `300` сек. Столько игроки будут видеть предупреждения |
| `LOG_LEVEL` | Enter = `INFO`. На время первой настройки удобнее `DEBUG` |
| Лог в файл | Enter = `1`, логи лягут в `service/logs/` |

Установщик **не запускает** сервис — это следующий шаг.

### Шаг 5. Проверить связь с панелью ДО запуска

```bash
sudo ./test-pelican.sh
```

Ждём `Итого: успешно N, ошибок 0`.

Если есть ошибки — **не запускайте сервис**, сначала исправьте. Скрипт печатает
конкретную причину: не тот тип токена, опечатка в URL, нет прав `control.start`.
Разбор частых ответов — в [README.md](README.md#устранение-проблем).

Предупреждение «Серверы с PELICAN_IMAGE... не найдены» на этом этапе — **норма**,
если вы ещё не создали CS2-серверы в панели.

### Шаг 6. Первый запуск — скачивание игры

```bash
sudo systemctl start cs2-updater.service
```

⚠️ **Первый старт качает ~40 ГБ и занимает от 20 минут до нескольких часов.**
Смотрите за процессом:

```bash
sudo journalctl -u cs2-updater.service -f
```

Ожидаемая последовательность:

```
[RUNNING] Выполняем первоначальную установку CS2...
[RUNNING] Устанавливаем SteamCMD...
[SUCCESS] SteamCMD установлен.
[RUNNING] Запускаем SteamCMD для установки/обновления CS2 (appid 730)...
 ... прогресс SteamCMD ...
[SUCCESS] CS2 успешно установлена/обновлена.
[INFO] CS2 Updater запущен.
```

Выйти из просмотра лога — `Ctrl+C`, сервис продолжит работать.

Убедиться, что игра на месте:

```bash
ls -la /home/cs2_base/server/game/csgo/steam.inf
```

(подставьте свой `BASE_DIR`). Файла нет — смотрите лог, SteamCMD не доработал.

### Шаг 7. Автозапуск при перезагрузке

`install.sh` уже сделал `systemctl enable`. Проверьте:

```bash
systemctl is-enabled cs2-updater.service
```

Ожидаемо: `enabled`.

### Шаг 8. Отдать файлы игры контейнерам

Дальше — настройка mount в Wings и панели, **три обязательных шага**:
`allowed_mounts` в конфиге Wings, создание mount в панели, добавление mount
на каждый сервер.

Всё расписано в [README.md → Точка монтирования в Pelican](README.md#точка-монтирования-в-pelican).
Пропустите любой из трёх — контейнер увидит пустой `/mnt` и сервер не запустится.

### Шаг 9. Импортировать egg и создать сервер

Панель → **Admin** → **Eggs** → **Import Egg** → файл `egg/pelican.yaml` из
этого же репозитория.

Создайте CS2-сервер на этом egg, добавьте ему mount, запустите. В консоли сервера
должно появиться `Mount /mnt проверен, файлы игры на месте.`

### Шаг 10. Оповещения игроков (опционально)

О рестарте updater сообщает командой `css_restart_notify <секунды>` — её понимает
плагин [NotifyMessages](https://github.com/Armatura-Create/NotifyMessages).

Без плагина обновления работают штатно, просто игроки не увидят предупреждения:
команда молча игнорируется сервером.

Поставили плагин — проверьте связку, отправив из консоли сервера в панели:

```
css_restart_notify 60
```

В чате должно появиться сообщение о рестарте. Если нет — в `Settings.json`
плагина проверьте `RestartNotify.Enabled` и наличие шаблона для `60`
в `Thresholds` (либо непустой `DefaultMessage`).

## Обновление

Занимает 5–10 минут. **Игровые серверы при этом не выключаются** — updater только
следит за версией, его перезапуск они не замечают.

Обновление `service/` не зависит от egg и docker-образа: их можно обновить отдельно
и позже.

### Шаг 1. Перейти в каталог сервиса

Забыли, куда ставили:

```bash
systemctl show -p WorkingDirectory --value cs2-updater.service
```

```bash
cd "$(systemctl show -p WorkingDirectory --value cs2-updater.service)"
```

### Шаг 2. Убедиться, что прямо сейчас не идёт обновление CS2

Самый опасный момент. Если updater уже погасил серверы и качает патч, а вы его
убьёте — **серверы останутся выключенными**.

```bash
sudo journalctl -u cs2-updater.service -n 40 --no-pager
```

- Видите `Останавливаем сервер ...` или `Запускаем SteamCMD` **без** последующего
  `Запускаем сервер ...` → идёт обновление, подождите 3–15 минут.
- Видите `Сервер уже на актуальной версии` или тишину → можно продолжать.

Для верности загляните в панель: все CS2-серверы должны быть running.

### Шаг 3. Сохранить конфиг и текущую версию

```bash
sudo cp .env ~/cs2-env-backup-$(date +%F-%H%M)
```

```bash
git rev-parse --short HEAD
```

Запишите хеш — он понадобится для отката.

### Шаг 4. Проверить локальные правки

```bash
git status --short
```

Пусто — идём дальше. Есть строки `M service/...` (вы правили скрипты руками) —
сохраните их, иначе `git pull` откажется работать:

```bash
sudo git stash push -m "локальные правки перед обновлением"
```

### Шаг 5. Остановить сервис

**Не пропускайте этот шаг.** Bash читает выполняющийся скрипт с диска по мере
выполнения. Подмените `start.sh` на работающем сервисе — и он продолжит исполнение
уже из нового файла со старого байтового смещения, то есть выполнит обрывок строки.

```bash
sudo systemctl stop cs2-updater.service
```

```bash
systemctl is-active cs2-updater.service
```

Ожидаемо: `inactive`.

### Шаг 6. Забрать обновление

```bash
sudo git pull origin master
```

```bash
git log --oneline -3
```

Если пул ругается `Your local changes would be overwritten` — вернитесь к шагу 4.

### Шаг 7. Проверить права на `.env`

В нём пароль Steam и оба токена панели. Старый установщик создавал файл с правами
`644` — читать мог любой пользователь машины. Новый ставит `600`, но уже существующий
файл нужно поправить руками:

```bash
sudo chmod 600 .env && ls -l .env
```

Ожидаемо: строка начинается с `-rw-------`.

### Шаг 8. Проверить конфигурацию

```bash
sudo ./test-pelican.sh
```

Ошибок быть не должно. Если появились — разбирайтесь до запуска.

### Шаг 9. Запустить и посмотреть лог

```bash
sudo systemctl start cs2-updater.service
```

```bash
sudo journalctl -u cs2-updater.service -f
```

Ждём `[INFO] CS2 Updater запущен.` и дальше тишину — значит патча нет, всё в порядке.
Строк `[ERROR]` и повторяющихся рестартов сервиса быть не должно. `Ctrl+C` для выхода.

### Шаг 10. Что проверить при первом реальном патче

Последовательность в логе должна быть такой:

```
Доступна новая версия CS2: ...
Оповещаем игроков командой css_restart_notify, отсчёт 300 сек.
Останавливаем сервер <id>
Запускаем SteamCMD для установки/обновления CS2
CS2 успешно установлена/обновлена.
Запускаем сервер <id>
```

```bash
sudo systemctl stop cs2-updater.service
```

```bash
sudo git reset --hard ХЕШ_ИЗ_ШАГА_3
```

```bash
sudo systemctl start cs2-updater.service
```

`.env` откат не затрагивает — он не хранится в git.

## Чего делать НЕ надо

- ❌ **Не запускайте `./install.sh` для обновления.** Он задаст все вопросы заново
  и перезапишет `.env` — потеряете токены. Он только для установки с нуля.
- ❌ Не делайте `git pull` на работающем сервисе (шаг 5).
- ❌ Не удаляйте `$BASE_DIR/server` — это файлы игры для всех контейнеров сразу.
- ❌ Не переносите каталог репозитория после установки — путь зашит в systemd-юните.

## Частые проблемы

**Сервис перезапускается в цикле.** Смотрите `journalctl -u cs2-updater.service -n 50`.
Обычно нет `.env` (запустили не из того каталога) или в нём синтаксическая ошибка.

**`Не удалось определить локальную версию (steam.inf не найден)`.**
SteamCMD не доскачал игру. Проверьте место на диске и запустите сервис заново —
докачка продолжится с прерванного места.

**`Не удалось получить список серверов (application API), HTTP 403/404`.**
Проблема в токенах или URL. Запустите `./test-pelican.sh` — он скажет, что именно.
Updater при этом не падает: файлы игры обновит, но серверы гасить и поднимать не сможет.

**Контейнер пишет `Mount /mnt пуст или не смонтирован`.**
Один из трёх шагов настройки mount не сделан. Чаще всего забыт `allowed_mounts`
в `/etc/pelican/config.yml` на ноде. См. [README.md](README.md#точка-монтирования-в-pelican).

**Игроки не видят предупреждений о рестарте.**
Нужен плагин NotifyMessages, шаг 10 установки.

## Удаление

```bash
sudo systemctl disable --now cs2-updater.service
```

```bash
sudo rm /etc/systemd/system/cs2-updater.service && sudo systemctl daemon-reload
```

```bash
sudo rm -rf /opt/cs2-updater
```

Файлы игры удаляются отдельно и **только если больше не нужны ни одному серверу**:

```bash
sudo rm -rf /home/cs2_base
```
