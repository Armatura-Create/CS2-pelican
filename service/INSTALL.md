# Установка и обновление CS2 Updater

Ставится **на хост-машину** (там же, где Wings), не в контейнер.
Устанавливается и обновляется одной командой — скрипт качает архив релиза,
проверяет контрольную сумму и всё настраивает.

Справочник по переменным, настройке mount и разбору проблем — в [README.md](README.md).

---

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/Armatura-Create/CS2-pelican/master/install.sh | sudo bash
```

Спросит каталог (по умолчанию `/opt/cs2-updater`), скачает и проверит архив
последнего релиза и запустит **мастер настройки**. Мастер сам находит всё, что
может, и сразу проверяет ответы — неверный ключ или адрес не всплывёт через час
в логах.

> **Не любите `curl | bash`?** Скачайте, прочитайте, запустите:
> ```bash
> curl -fsSLO https://raw.githubusercontent.com/Armatura-Create/CS2-pelican/master/install.sh && less install.sh && sudo bash install.sh
> ```

### Что приготовить заранее

Только адрес панели и **два разных** API-ключа из неё:

1. **Application API ключ** — панель → **Admin** → API Keys, начинается с `papp_`.
   Права на чтение Servers, Nodes, Eggs и Mounts.
2. **Client API ключ** — меню аккаунта → API Keys, начинается с `pacc_`.
   Аккаунт должен иметь права **control** и **console** на CS2-серверы.

Перепутаете ключи — мастер скажет об этом сразу. На остальные вопросы обычно
хватает Enter.

### Что делает мастер

| Шаг | Что происходит |
|---|---|
| 1. Зависимости | ставит только недостающие пакеты |
| 2. Панель | адрес можно вставить прямо из браузера (`…/admin/servers`) — лишнее отрежется; оба ключа проверяются запросом к панели, ввод скрыт |
| 3. Нода и серверы | показывает ноды панели и **отмечает ту, что указывает на этот сервер**; показывает образы серверов на ноде и какими серверами будет управлять updater |
| 4. Оповещения | по `ADDON_PLATFORM` серверов **предлагает команду** плагина: `sw_`/`css_`/`mm_restart_notify` или своя; время отсчёта |
| 5. Файлы игры | каталог, свободное место; если CS2 уже скачана — скажет, что качать не придётся |
| 6. Wings и панель | проверит `allowed_mounts` в Wings и **предложит добавить** каталог сам (с копией конфига и перезапуском Wings, игровые серверы не останавливаются); проверит, что в панели есть Mount и что egg импортирован и **не устарел** |
| 7. Сервис | имя (по умолчанию `cs2-updater`), автообновление, дополнительные настройки: Steam-аккаунт, AppID, интервал, логи |

В конце — итог со всеми значениями (ключи замаскированы) и вопрос «Всё верно?».
Ответ «нет» — пройти мастер ещё раз, ваши ответы станут значениями по умолчанию.
После сохранения мастер предложит запустить сервис и напишет, **что осталось сделать
руками** — обычно это только Mount и egg в панели.

### Повторный запуск: обновить, перенастроить, удалить

Та же команда на уже настроенном сервере показывает меню:

```
CS2 Updater уже установлен: /opt/cs2-updater, версия v1.2.9, сервис: cs2-updater.service, active.
  1) Обновить до последней версии
  2) Перенастроить — текущие значения будут предложены по умолчанию
  3) Удалить
  4) Выйти
```

**Перенастроить** — сначала обновляет до последней версии, потом запускает мастер,
где все текущие значения стоят по умолчанию (ключи — тоже: Enter их оставляет).
Меняете одно поле — меняется одно поле. Если в этот момент идёт обновление CS2,
мастер дождётся его конца и только потом перезапустит сервис.

Мастер можно запустить и напрямую: `sudo /opt/cs2-updater/configure.sh`.

### Требования

| | |
|---|---|
| ОС | Debian 11+ / Ubuntu 20.04+ (`apt`, `systemd`) |
| Права | root или sudo |
| Диск | **не меньше 50 ГБ** свободно под файлы игры |
| Панель | Pelican Panel + Wings, доступна с этой машины |
| Терминал | интерактивный — скрипт задаёт вопросы |

### Настройки установки

Передаются перед `bash`:

```bash
curl -fsSL .../install.sh | sudo INSTALL_DIR=/srv/cs2-updater bash
```

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `INSTALL_DIR` | спросит, предложит `/opt/cs2-updater` | куда ставить |
| `VERSION` | `latest` | поставить конкретную версию, например `v1.0.0` |
| `BASE_URL` | GitHub Releases | зеркало для закрытых сетей |

### Первый запуск

⚠️ **Качает ~40 ГБ, от 20 минут до нескольких часов.** Скрипт предложит запустить
сервис в конце; следите за процессом:

```bash
sudo journalctl -u cs2-updater.service -f
```

Ожидаемая последовательность:

```
[RUNNING] Выполняем первоначальную установку CS2...
[RUNNING] Устанавливаем SteamCMD...
[RUNNING] Запускаем SteamCMD для установки/обновления CS2 (appid 730)...
[SUCCESS] CS2 успешно установлена/обновлена.
[INFO] CS2 Updater запущен.
```

Проверить, что игра на месте:

```bash
ls -la /home/cs2_base/server/game/csgo/steam.inf
```

### Что сделать в панели после установки

Три обязательных шага, без любого из них контейнер увидит пустой `/mnt`. Мастер
проверяет все три и в конце пишет, какие остались:

1. **Wings** — `BASE_DIR` в `allowed_mounts` (`/etc/pelican/config.yml`), затем
   `sudo systemctl restart wings`. Мастер предложит сделать это сам.
2. **Панель** — Admin → Mounts → source `$BASE_DIR/server`, target `/mnt`, Read Only
3. **Сервер** — Admin → сервер → Mounts → **+** → перезапуск

Подробно: [README.md → Точка монтирования в Pelican](README.md#точка-монтирования-в-pelican).

Затем импортируйте egg: панель → Admin → Eggs → Import Egg → `egg/pelican.yaml`
из [репозитория](https://github.com/Armatura-Create/CS2-pelican).

### Оповещения игроков (опционально)

О рестарте updater сообщает командой плагина
[NotifyMessages](https://github.com/Armatura-Create/NotifyMessages) — `<команда> <секунды>`.
Префикс команды зависит от фреймворка на серверах, установщик спрашивает, какую слать:

| Фреймворк на серверах | `RESTART_NOTIFY_CMD` в `.env` |
|---|---|
| Swiftly | `sw_restart_notify` (по умолчанию) |
| CounterStrikeSharp | `css_restart_notify` |
| MetaMod | `mm_restart_notify` |
| другой | своя команда, одно слово |

Поменять позже — отредактируйте `RESTART_NOTIFY_CMD` в `/opt/cs2-updater/.env` и
перезапустите сервис. На установках старше v1.2.8 строка появится в `.env` сама
при первом запуске новой версии, со значением `sw_restart_notify`.

Без плагина обновления работают штатно, просто игроки не увидят предупреждений.
Проверить связку — из консоли сервера в панели (для Swiftly):

```
sw_restart_notify 60
```

## Обновление

```bash
curl -fsSL https://raw.githubusercontent.com/Armatura-Create/CS2-pelican/master/update.sh | sudo bash
```

Игровые серверы при этом **не выключаются** — updater только следит за версией,
его перезапуск они не замечают.

Скрипт делает всё сам:

1. находит установку по systemd-юниту;
2. **отказывается работать, если прямо сейчас идёт обновление CS2** — от отсчёта
   для игроков до запуска серверов (по локу `/run/cs2-updater-cycle.lock`); прервать
   цикл значит оставить игровые серверы выключенными;
3. качает релиз и сверяет контрольную сумму — при несовпадении не трогает ничего;
4. сравнивает версии, при совпадении просто выходит;
5. останавливает сервис **до** подмены файлов;
6. делает бэкап каталога;
7. подменяет файлы, сохраняя `.env` и `logs/` (их в архиве нет — они появляются
   при работе сервиса);
8. чинит права на `.env`, проверяет панель, поднимает сервис;
9. **если сервис не поднялся или падает в первые 40 секунд — автоматически
   откатывается** на прежнюю версию; хранит 3 последних бэкапа.

### Автообновление

Сервис может обновлять себя сам: каждую ночь между 04:00 и 05:00 проверяет
GitHub и ставит новый релиз тем же `update.sh`, со всеми проверками выше.
Установщик спрашивает об этом при установке; включить или выключить позже:

```bash
sudo /opt/cs2-updater/autoupdate.sh on
sudo /opt/cs2-updater/autoupdate.sh off
sudo /opt/cs2-updater/autoupdate.sh status
```

- Работает от systemd-таймера `cs2-updater-autoupdate.timer`, в отдельной
  от сервиса cgroup: остановка сервиса не убивает того, кто его обновляет, а
  сломанный `start.sh` не мешает поставить исправление.
- Запускает `update.sh` из каталога установки — только код опубликованного
  релиза с проверенной контрольной суммой, не с `master`.
- Если ночью идёт обновление CS2, автообновление пропускает эту ночь.
- Нужна версия v1.2.6 или новее: в старых архивах нет `update.sh`. Если сейчас
  стоит старая — один раз обновитесь командой выше, потом `autoupdate.sh on`.
- Хотите закрепить конкретную версию — выключите автообновление, иначе ночью
  поставится последняя.

Логи ночных запусков: `sudo journalctl -u cs2-updater-autoupdate.service`.

### Настройки обновления

| Переменная | Зачем |
|---|---|
| `VERSION=v1.0.0` | поставить конкретную версию (в том числе откатиться назад) |
| `INSTALL_DIR=/путь` | если автопоиск не нашёл установку |
| `FORCE=1` | обновлять даже посреди цикла обновления CS2 — **опасно**, серверы могут остаться выключенными |

### Откат

Скрипт печатает готовую команду отката в конце работы. Общий вид:

```bash
curl -fsSL https://raw.githubusercontent.com/Armatura-Create/CS2-pelican/master/update.sh | sudo VERSION=v1.0.0 bash
```

Либо вручную из бэкапа, который update.sh оставляет рядом
(`/opt/cs2-updater.backup-ГГГГММДД-ЧЧММСС`):

```bash
sudo systemctl stop cs2-updater.service && sudo rm -rf /opt/cs2-updater && sudo mv "$(ls -1d /opt/cs2-updater.backup-* | tail -n1)" /opt/cs2-updater && sudo systemctl start cs2-updater.service
```

`.env` откат не затрагивает ни в одном из вариантов.

## Чего делать НЕ надо

- ❌ **Не обновляйтесь через `configure.sh`.** Это мастер настройки: файлы он не
  обновляет. Для обновления — `update.sh` или пункт «Обновить» в меню установщика.
- ❌ Не подменяйте файлы на работающем сервисе. Bash читает выполняющийся скрипт
  с диска по смещению и продолжит с того же места уже в новом файле — выполнится
  обрывок строки. `update.sh` поэтому и останавливает сервис первым делом.
- ❌ Не удаляйте `$BASE_DIR/server` — это файлы игры сразу для всех контейнеров.
- ❌ Не переносите каталог установки — путь зашит в systemd-юните.

## Частые проблемы

**Сервис перезапускается в цикле.** `sudo journalctl -u cs2-updater.service -n 50`.
Обычно нет `.env` или в нём синтаксическая ошибка.

**`Не удалось определить локальную версию (steam.inf не найден)`.**
SteamCMD не доскачал игру. Проверьте место на диске и перезапустите сервис —
докачка продолжится с прерванного места.

**`Не удалось получить список серверов (application API), HTTP 403/404`.**
Проблема в токенах или URL. Запустите `sudo /opt/cs2-updater/test-pelican.sh` —
он скажет, что именно. Updater при этом не падает: файлы игры обновит,
но серверы гасить и поднимать не сможет.

**Контейнер пишет `Mount /mnt пуст или не смонтирован`.**
Один из трёх шагов настройки mount не сделан. Чаще всего забыт `allowed_mounts`
в Wings.

**`update.sh` не нашёл установку.** Укажите каталог явно:
`curl ... | sudo INSTALL_DIR=/opt/cs2-updater bash`.

**Игроки не видят предупреждений о рестарте.** Нужен плагин NotifyMessages.

## Удаление

Запустите установщик ещё раз и выберите **«Удалить»**:

```bash
curl -fsSL https://raw.githubusercontent.com/Armatura-Create/CS2-pelican/master/install.sh | sudo bash
```

Он попросит ввести слово «удалить», дождётся конца обновления CS2, если оно идёт,
и уберёт сервис, таймер автообновления, каталог установки и бэкапы. Файлы игры
(~40 ГБ) спросит отдельно — по умолчанию оставит: их могут монтировать серверы.
Mount в панели и `allowed_mounts` в Wings не трогает.

Вручную то же самое:

```bash
sudo systemctl disable --now cs2-updater.service cs2-updater-autoupdate.timer
```

```bash
sudo rm -f /etc/systemd/system/cs2-updater.service /etc/systemd/system/cs2-updater-autoupdate.* && sudo systemctl daemon-reload
```

```bash
sudo rm -rf /opt/cs2-updater /opt/cs2-updater.backup-*
```

Файлы игры удаляются отдельно и **только если больше не нужны ни одному серверу**:

```bash
sudo rm -rf /home/cs2_base
```
